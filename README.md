# 蓝色大肥鱼语音与曲库管理 v0.3.1

面向 AstrBot 的开源QQ语音与曲库插件，使用MIT许可证。在原生插件页面管理预置音频，支持配置自己的专属克隆音色。普通聊天仍用文字；用户明确请求时才发送语音或播放歌曲。

## 安装与首次配置

运行要求：AstrBot 4.29.1或更新版本、Python 3.10+、可执行的 `ffmpeg` 与 `ffprobe`。目前只支持QQ的 `aiocqhttp`/NapCat消息链路；其他平台未验证。

1. 在 AstrBot 插件管理中安装本仓库或导入Release源码ZIP。
2. 填写要授权的QQ平台ID与群白名单；默认不授权任何群。
3. 若只使用预置曲库，不需要配置语音API密钥。
4. 要启用朗读，在现有硅基流动embedding提供商中配置凭据，再将提供商ID填入 `speech_credential_provider_id`。默认内置女声 `claire`，不会自动克隆他人的声音。
5. 使用自定义音色：`voice`选`custom`并填写服务器私有的 `custom_voice_uri`；从旧版迁移请先阅读 [迁移说明](docs/MIGRATION.md)。不要把私有引用改回源码。

首次使用 `/语音帮助` 检查配置状态。配置就绪不等于已通过云端试听或QQ客户端播放验收。

## 离线备份与安全恢复（0.3.1）

新增离线工具，将原音与曲目元数据打包为带SHA256清单的私有ZIP；完整校验后只恢复到尚不存在的新目录，且所有歌曲默认暂停点播。不收集账号配置、密钥、音色映射或使用记录，也不调用模型与QQ。

```powershell
python scripts/manage_library.py backup --data-dir "<插件私有数据目录>" --output "<私有备份目录>/library.zip"
python scripts/manage_library.py verify --archive "<私有备份目录>/library.zip"
python scripts/manage_library.py restore --archive "<私有备份目录>/library.zip" --destination "<尚不存在的新目录>"
```

**这类备份含音频和元数据、未加密，不能公开到GitHub。** 只读备份不改原库，失败不覆盖旧备份；恢复中断会保留隔离标记，新目录不要直接投入运行。详细范围、上限与失败处理见 [备份说明](docs/BACKUP.md)。

## 曲库与语音能力

- **原件保护**：同名上传不覆盖，重命名/删除/设置需要最新版本标识；原音不因播放或试听被重新编码。
- **曲目设置**：最多12个别名、200字说明、启用/暂停点播；新增上传默认草稿，现有旧曲库无需搬迁并保持原有可点播状态。
- **安全上传**：50MB以内、10分钟以内可解码音频；支持 MP3/WAV/M4A/OGG/FLAC。校验失败不进入曲库。原生上传分块落盘，兼容 Base64 上传仅允许4MB以内。
- **小内存试听**：管理页面只生成前30秒压缩试听，完整原音通过单独下载接口流式提供。
- **完整歌曲播放**：与短TTS的限制分离，曲库音频最长支持10分钟；群语音会生成压缩副本，不能把QQ语音播放称为无损高清。
- **避免误扣费**：未知歌名、暂停歌曲和无法区分的多个版本不自动转成付费语音；即兴生成使用独立入口。
- **页面交互**：搜索歌名/别名/说明、状态筛选、草稿设置弹窗、原音下载、特殊歌名安全显示、响应式布局和主题适配。

## 群聊使用

```text
@蓝色大肥鱼 /播放 人是猫
@蓝色大肥鱼 /播放人是猫完整版
@蓝色大肥鱼 /歌单
@蓝色大肥鱼 /语音 同学们上课路上注意安全呀～
@蓝色大肥鱼 /语音帮助
```

支持 `/唱歌`、`/点歌`、`/放歌`、`/听歌` 点播别名。无空格快捷指令须带 `/`；普通自然语言由已有对话模型判断，避免把“说得有道理”“唱得真好”误当命令。

自然语言例子：`@蓝色大肥鱼 播放小蓝鲸翻唱的完整版`。模型可以使用 `whale_song_catalog` 查询可点播曲目和别名，再调用 `whale_sing_short_song`。预置翻唱是已经准备好的音频，不是每次实时重新演唱；原始点播不需要语音合成接口，普通自然语言理解仍可能调用现有聊天模型。

## 曲库管理

在 AstrBot 侧栏的 **蓝色大肥鱼语音与曲库管理 → 预置曲库管理** 中：

1. 选择音频，按需要修改点播名称，点击“上传并校验”。
2. 上传成功保存为草稿，填写别名、说明，勾选“允许群内点播”并保存。
3. 用搜索和状态筛选定位歌曲；“试听”播放前30秒，“原音”下载原始文件。
4. 字节相同的原音换名上传会提示已有曲目；点击“查看”定位原件，不会重复保存或自动启用草稿。
5. 重命名保留别名和启停设置；删除原音是不可撤销的操作，需要确认。
6. 如果提示“版本已变化”，刷新后核对，不要盲目重复提交。

固定容量边界：最多500首，全库音频及未清理的上传暂存合计1GB。不会为了腾空间自动删除已有歌曲。

## 即兴歌唱与专属音色

说话使用管理员配置的硅基流动凭据。内置音色可直接选择；私有克隆音色从 `custom_voice_uri` 或数据目录的 `voice-aliases.json` 读取，不随开源源码分发。升级迁移不需要重新上传参考音频或重建音色。

**专属克隆音色不等于已经开通真正歌唱服务。** 配置 MiMo TTS（风格提示为“唱歌”）并在 `sing_provider_id` 中绑定后，可使用：

```text
@蓝色大肥鱼 /即兴唱 小鲸鱼游呀游，今天课表排好啦。
```

`whale_create_short_song` 仅处理明确的新歌生成需求，最多160字。没有歌唱提供商时如实提示，不自动用普通朗读冒充演唱。

为兼容旧版实验，保留 `allow_experimental_tts_singing` 开关，默认关闭。管理员明确打开后，**只有 `/即兴唱` 或相应生成工具**可以试用普通TTS的 `[singing]` 标签；不保证旋律与唱腔，可能产生语音费用，曲库未命中永远不自动使用它。

## 权限、存储与故障边界

- 保留原平台、群白名单和管理员私聊授权。定时任务不能调用音频生成/点播工具，未授权聊天不能查看歌单。
- 同一消息只提交一次，用户冷却30秒，每日10次、全插件100次，按北京时间重置。失败或状态不明不自动重试。
- `songs/` 保存原音，`song-library.json` 保存别名/启停等资料；索引损坏时曲库停止修改和点播，不静默清零。语音功能尽量独立保持可用。
- 上传、编辑、删除串行执行；取消请求会等待磁盘任务退出，避免还在写文件时提前释放锁。播放先创建私有副本，避免原歌被重命名/删除后播放中断。
- 音频解析只允许本地文件协议及指定音频容器，不接受远程播放列表；不需要在2G服务器部署语音大模型。
- 操作记录不保存朗读原文或歌词；`network_attempted=false` 可区分预置曲库播放与云端合成。`submitted_to_qq` 不是所有客户端已可播放或对方已收听的证明。
- 缓存保留至24小时后的下一次清理；下载副本在传输结束后删除。原音与设置请在管理员自己的备份方案中备份。

## 验证方法

```powershell
python scripts/run_tests.py
```

测试使用临时曲库、模拟云端响应和QQ发送替身，不发起付费合成或往真实群里发送。Windows下创建符号链接可能需要额外权限，对应测试会明确标为跳过；Linux服务器应另外运行这些用例。页面还需要浏览器协议桩及真实 AstrBot 内嵌页面验收。

仓库与Release只包含软件源码，不分发歌曲、参考录音、服务商凭据或部署专用音色引用。请分别备份这些私有运行数据。

构建发布包：

```powershell
python scripts/check_public_tree.py
python scripts/build_release.py
```

输出为 `build_artifacts/` 下的ZIP与SHA256。归档包含 `PUBLIC_FILES.json` 文件清单，不包含运行数据。构建不会覆盖内容不同的同版本归档。

GitHub工作流会在合并/推送后运行离线检查，`v版本号`标签须与三个版本声明一致；发布工作流先检查再创建Release。不需要也不应在CI中配置语音服务密钥。
